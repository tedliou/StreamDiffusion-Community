Fork proposal · 2026-10-21 · v3（決策全部定案）

StreamDiffusion → sd-turbo 即時 NDI 引擎

把 StreamDiffusion 改造成 Windows 專用、針對 sd-turbo 單步 img2img 極致優化、clone 後一鍵啟動，並以 NDI 串接 TouchDesigner 的即時生成引擎。本頁為盤點、調查與分析後的提案，尚未修改任何程式碼。

TouchDesigner→ NDI / Spout →GPU 前處理→TAESD enc→UNet ×1 step→TAESD dec→ NDI / Spout →TouchDesigner

01摘要與本機環境

  • 可行性高。所需元件在 2026-10 皆有 Windows 官方 wheel：torch 2.14.1、TensorRT 11.4、cyndilib 0.1.3（已實測：wheel 內含 NDI runtime DLL，免另裝 NDI）。
  • sd-turbo 只需 1 步、guidance=0。論文的 Stream Batch 與 RCFG 在這情境下幾乎用不到；真正的瓶頸會是 I/O、前後處理、CPU↔GPU 同步。
  • 最大收益在「管線化」而非模型本身。現有程式碼每幀強制同步、前後處理走 CPU/PIL，這部分改到 GPU 上並重疊執行，預期收益大於換新版 TensorRT。
  • 建議重寫核心，不是修補。現有 wrapper 的抽象是 SD1.5 + LCM 多步時代的產物，sd-turbo 專用路徑可以大幅簡化。

02論文技術拆解

StreamDiffusion（arXiv 2312.12491）六項技術，對照 sd-turbo 單步情境的實際價值。

技術做什麼論文收益對 sd-turbo 1 步
Stream Batch把不同幀的不同去噪步合成一個 batch，一次 UNet 推進所有幀≈1.5×（多步時）無效 只有 1 步，batch=1
RCFG用殘差雜訊當虛擬負向，免跑負向 UNet2.05×（5 步）無效 sd-turbo 官方建議 guidance=0
I/O 佇列前處理、推論、後處理分執行緒未單獨量測關鍵 現有程式碼其實沒做到，需重做
SSF 相似幀過濾畫面幾乎不變時機率性跳過推論靜態畫面省電 2–2.4×保留並改良 裝置現場常有靜態畫面
預先計算prompt embedding、雜訊、排程係數一次算好—保留
TAESD + TensorRT小型 VAE、UNet/VAE 編譯為 TRT engine1 步：21.3 → 10.65 ms（4090）核心加速

論文數據（RTX 4090）與 3070 推估

設定4090 實測3070 推估說明
sd-turbo 1 步 + TRT10.65 ms · ~94 fps≈ 25–30 ms · 33–40 fps推估依 FP16 算力比例，需以 benchmark 驗證
sd-turbo 1 步，無 TRT21.34 ms≈ 50–60 msPyTorch 路徑，作為保底
LCM-LoRA 4 步 + TRT26.93 ms—本提案不再以此為主
  • 論文自述限制：無時間一致性（閃爍）、TRT engine 為靜態尺寸、Stream Batch 吃 VRAM、Self-negative RCFG 會拉高對比。
  • StreamDiffusionV2（2025）改為影片擴散模型（Wan 1.3B/14B、多張 H100），不能直接套用；可借鏡的是 rolling KV cache 與 motion-aware noise 的想法。

驗收指標（每個里程碑量測）

  • 吞吐量：512×512 與 640×360 下的 fps。3070 目標：TensorRT ≥ 30 fps。
  • 端到端延遲：TD 送出時間戳圖樣，回收後比對。目標 ≤ 3 幀。
  • 資源：VRAM 峰值、GPU 使用率、功耗（NVML）。
  • 品質：相鄰幀差（閃爍指標）與固定測試影片的目視比較。

13決策紀錄

已決定

項目決定對提案的影響

以下全部採用建議（2026-10-21 確認）

1. GUI 形式
建議：本機 Web GUI（瀏覽器開 localhost，可用平板遠端操作）。替代：原生視窗（Dear PyGui，單機但較快上手）、或只做 OSC 讓 TouchDesigner 當操作介面。
2. 支援的最低顯卡
建議：RTX 20 系列以上、VRAM ≥ 8 GB。CUDA 13 與 TensorRT 11 都已不支援 GTX 10 系列。RTX 3070 作為參考機。
4. 加速後端
建議：TensorRT 11 為主，PyTorch 保底，TensorRT-RTX 列為實驗。TRT 11 速度最好，但每台 GPU 首次要建置 engine（數分鐘）。
6. 專案與套件名稱
建議：改名，避免與上游 PyPI 套件 streamdiffusion 衝突，並在 README 註明 fork 來源。
7. 是否保留 SD1.5 + LCM 多步路徑
建議：先移除，以 ModelSpec 抽象保留未來擴充的位置。Stream Batch 與 RCFG 的程式碼留在 git 歷史可查。
8. 文件語言
建議：README 用正體中文加英文摘要，刪除日文與韓文版。
9. 生成解析度與輸出尺寸
建議：以 512 級解析度生成（例如 640×360），送出前在 GPU 上放大到 TD 要的尺寸（例如 1280×720）。sd-turbo 在 512 附近訓練，直接生成 720p 會變慢且構圖較差。
